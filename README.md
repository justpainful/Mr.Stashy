# Stashy

**Catch it. Keep it.** Stashy is a local-first iOS archive for public posts and direct public media. It is designed to preserve a post's text, attribution, ordered media, and source metadata on the device rather than sending an archive to a Stashy service.

> Release status: this repository is under active release validation. Do not treat a platform as supported until its live contract status is `passing` in the generated support report. Current code deliberately exposes only the capabilities backed by that report.

## What it is built to do

- Paste or share a public URL, inspect every detected item, and choose a full-post archive, media-only save, or text card.
- Keep archives local with a JSON manifest, verified media files, a SQLite metadata/search index, and `.stash` import/export.
- Provide four native tabs: Catch, Library, Queue, and Settings, plus a Share Extension that hands URLs to the app through its App Group.
- Work offline after a successful save, subject to local media codec support.
- Use English and Arabic localization, including RTL-aware SwiftUI layout.

The product never creates a Stashy account, backend, analytics stream, cloud library, ad profile, remote flag, or tracking record. Network access is limited to a source platform or media host after a user explicitly asks Stashy to resolve or download a link.

## Support matrix

`Artifacts/PlatformSupport.md` is generated by the live contract suite and is the only publishable source of platform support. It is produced by:

```bash
make platform-contracts
```

The app must not display an unverified platform as supported. YouTube remains omitted from production capability exposure unless its own live contract status is `passing`. Direct public media URLs are tested independently from social-platform resolvers.

## Screenshots

Final reviewed screenshots are generated, not hand-picked, by the screenshot workflow and stored under `Artifacts/Screenshots/`. The required release set covers onboarding, Catch, mixed results, Queue, both Library modes, Living Post, text cards, Settings, Discord-disabled state, Arabic, and dark mode. This repository does not currently claim a final visual-review run until those files and `Docs/VisualQA.md` contain evidence.

## Requirements

- macOS 26 with Xcode 26.5.0 and the iOS 26.5 Simulator runtime.
- Tuist `4.64.1` (pinned in `.tuist-version` and `.tool-versions`).
- Python 3 with dependencies from `requirements-dev.txt` for asset validation.
- An available iPhone Simulator; scripts prefer a current Pro Max model, then another iPhone.

GitHub Actions uses the `macos-26` hosted image and selects `/Applications/Xcode_26.5.0.app/Contents/Developer` explicitly. See `Docs/CI.md` for the runner decision.

## Build and test

```bash
make bootstrap
make build
make test
make ui-test
make screenshots
LIVE_PLATFORM_CONTRACTS=1 make platform-contracts
make ipa
make release-check
```

`make release-check` fails closed: it requires real-alpha assets, passing release-gated contracts, unit and UI results, an unsigned IPA, the full screenshot set, generated support evidence, and the three quality audits.

## Unsigned IPA and sideloading

`make ipa` creates `Artifacts/MrStashy-unsigned.ipa`; the release workflow uploads it as **`MrStashy-unsigned.ipa`** together with `MrStashy-dSYM.zip`. It is intentionally unsigned so a device owner can re-sign it with a sideloading tool. See `Docs/Sideloading.md` for the process and limitations.

## Discord tools

Discord functionality, when implemented, accepts only a user-supplied **Discord bot token** through the app's secure storage. It must never accept a personal user token, automate a normal user account, or place a token in source control or logs. See `Docs/DiscordBotToken.md`.

## Known release limitations

- This README makes no claim that the required social-platform resolvers have passed live contracts.
- Final simulator, crash, memory, performance, accessibility, and visual-QA evidence is required before a release can be accepted.
- Character artwork is deliberately not asserted as production-integrated here. The current UI may use neutral illustration reserves while the visual system is finalized.
